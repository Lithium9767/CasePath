# CasePath

**面向普通用户的规则条件驱动法律信息检索与交互式解释系统 · 知识工程课程实践结项项目**

CasePath 将法条组织为规则与条件，将案例组织为事实认定、裁判理由和结果。
用户可以用日常语言提问；系统围绕相关规则检索案例、比较条件差异，并在关键事实缺失时追问，
最后提供带来源的条件化解释，而不是直接把几个相似案例拼成答案。

项目已完成课程阶段交付。本文按当前本地交付代码整理，文档整理日期为 **2026-11-06**；
结项不等于所有研究指标或生产化能力均已完成，具体边界见 [交付说明](docs/DELIVERY.md)。

## 系统流程

```text
离线：法条 → 结构化规则与条件 ─┐
                             ├→ 两层图谱投影 → Neo4j / 检索索引
      案例 → 事实、理由与结果 ─┘

在线：用户问题
      → A 混合规则召回与用途划分
      → B 用户事实增量映射到规则条件
      → C 案例召回、比较和角色组织
      → D 条件证据覆盖与分歧统计
      → E 识别关键缺失事实并生成追问
      → 证据化解释 / 用户补充后进入下一轮
```

- **混合检索**：BM25、语义向量、请求类型标签与固定 Cypher 图路径，使用加权 RRF 融合。
- **统一条件空间**：规则、用户事实和案例认定通过稳定的 `condition_id` 对齐。
- **增量交互**：保留历史证据、明确纠正及冲突；未知不自动视为否定。
- **案例对照**：区分支持、限制、边界与证据不足的候选，条件不同不直接等于不相关。
- **前端展示**：会话、条件矩阵、案例、引用及图谱；当前本地代码包含 Neo4j 分页全图与本轮路径高亮。

## 快速开始

在包含 `pyproject.toml` 的仓库根目录执行：

```powershell
uv sync --locked --extra api --extra live --group dev
uv run casepath-demo
```

这是无外部密钥的离线 Demo。正式 Live 需要配置模型、图谱及可选向量索引：

```powershell
# 首次配置时复制；已有 .env 不要覆盖
Copy-Item .env.example .env
# 编辑 .env，设置 CASEPATH_MODE=live 和所需服务配置
uv run --env-file .env uvicorn casepath.api.configured:create_configured_app --factory --host 127.0.0.1 --port 8000
```

另开终端启动前端：

```powershell
cd frontend
# 首次配置时复制；已有 .env 不要覆盖
Copy-Item .env.example .env
npm ci
npm run dev
```

浏览器访问 `http://localhost:5173`；接口文档为 `http://127.0.0.1:8000/docs`。
首次图谱导入、向量建库、Linux 命令和常见问题见 [运行指南](docs/RUNNING.md)。
`casepath.api.main:app` 始终是 Demo，不要误作正式算法入口。

## 使用边界

系统用于法律信息组织、检索与案例对照，不替代律师或法官作出最终法律判断。
会话默认采用单进程内存存储；未提供完整生产级鉴权、持久化和隐私隔离。
请勿直接公开部署或输入真实敏感案件材料。来源引用不自动等于已核验，
模型调用与 embedding 建库可能产生费用。

历史方案完整保留在 [README.history.md](README.history.md) 及文档索引中，不作为当前运行说明。
