原始交付存于 `data/inputs/rules/<sha256>.json`；可直接使用该路径重建。
扩展 manifest 采用内部发布格式2.0，不是把 RuleRecord 合同升级到2.0。
它绑定原始输入、四份输出、覆盖统计，并归档旧基线回执。
旧回执只描述五条保留规则，不覆盖新增771条；新增审核状态固定为 L1_unreviewed。

构建先在临时目录校验规则、案例桥接和完整图，再复用已有五文件发布/失败回滚事务。
输入内容寻址归档先于正式发布，失败最多留下不被当前 manifest 引用的输入副本。
在服务停止时发布并重启：多文件替换不是数据库快照事务，发布窗口读者可能校验失败。
旧五条构建器会拒绝覆盖扩展数据，避免误操作使规则库退回五条。
