# P4：LLM 证据注入与解释

正式工厂现在将结构化 LLM 同时注入条件投影与解释规划；默认 Demo 不变。解释不再仅拼接规则标题，也不把 D/E 内部指标说明当作回答正文。

## 注入内容

- 本轮问题、最近 16 条事实、最近 3 轮对话，以及条件状态和事实证据关联。
- 前 3 条候选规则的解释字段：CORE/DIAGNOSTIC、ALL/ANY、例外、后果、成熟度及法条原文 SourceSpan；去掉不参与解释的审计元数据。
- 每类最多 1 条深度案例：预定角色、查明事实、条件认定、裁判理由和结果分别保留。
- 完整证据包上限为 18,000 字符（不是 token 数）；规则或案例整体超限则不纳入，记录遗漏。原文引句不截断。基本输入仍超限则明确失败。

这些原始合同作为解释侧数据保留，不改变检索文本和索引版本；无需因此重新 embedding 建库。

## 提示词与验证

提示词在 `src/casepath/adapters/grounded_explanation.py` 的 `SYSTEM_PROMPT`。用户原话、文书和历史对话均作为不可信数据，不作为系统指令；要求回答当前问题、区分陈述和认定、未知和否定、事实和假设，不用模型记忆补法律依据。

模型输出结构化段落和条件分支。后端检查引用与事实 ID 白名单、分支规则与条件归属、目标规则原文引用，最后生成公开 ExplanationPlan 和数字引用标记。模型失败或非法输出不会伪装成成功的模板回答。

NEEDS_CLARIFICATION 轮次只返回原话回顾和问题卡，不调用完整解释模型。这是正常流程分支，不是生成失败后的伪装成功。READY_TO_EXPLAIN 才调用完整生成；失败仍按会话回滚处理。

没有注入模型时仍使用确定性摘要；没有完整规则记录时也不让模型凭记忆补证据。

## P1 分阶段调用预算

正式 DeepSeek 主机 api.deepseek.com 自动选用 max_tokens，显式发送 thinking；其他兼容服务仍使用原参数，不擅自发送 DeepSeek 专用字段。自定义代理主机不自动推测供应商，需要另加显式供应商配置后再接。

| 阶段 | 输出 token 上限 | 单次超时 | 重试 | DeepSeek 思考 |
|---|---:|---:|---:|---|
| relevance | 1000 | 45 秒 | 0 | disabled |
| projection | 1400 | 45 秒 | 0 | disabled |
| explanation | 1800 | 60 秒 | 0 | disabled |

可用 CASEPATH_LLM_STAGE_POLICIES 的 JSON 对象覆盖部分阶段字段；未写字段保持默认。旧全局预算仅作无阶段调用的后备。端口新增可选 stage 参数，第三方实现应同步接受。

例如：`{"projection":{"thinking":"enabled","max_tokens":4096,"timeout_seconds":90}}`。开启思考后要重新测准确性、token 与耗时，不把“关闭思考”说成法律质量已经达标。当前没有完成独立人工标注集的模式对照。

日志只记录阶段、耗时、用量和异常类型，不记录用户原文、API Key 或供应商错误正文。finish_reason=length 明确报错，拒收即便能解析但可能不完整的 JSON。

## 验证边界

ID 校验只能证明引用来自本轮证据包，不能证明每句话被证据语义蕴含。提示词也不是提示注入的绝对防护。所有引用仍为 `verified=False`；独立语义核验和法律专业复核尚未完成。L1 与深度案例不足警告继续保留，不自动提升成熟度。

## 生效与验收

重启正式 API 后新建会话验证；已经保存的历史快照不会自动重算。检查回答是否提及本轮原话、具体条件与原文证据，补充事实后解释是否相应改变，并检查引用面板。此修改不要求重建向量库。

自动测试覆盖：原文注入、引用/事实白名单、非法分支、结构化输出、模型失败不伪装成功、阶段预算与供应商参数、输出截断拒收、澄清轮不调用长解释。通常澄清轮两次模型调用，完整轮三次。自动替身测试不能替代真实模型端到端验收。
